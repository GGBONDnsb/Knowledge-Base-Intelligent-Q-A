# 云启科技业务数据字典

- 版本：v1.0
- 冻结日期：2026-09-10
- 适用项目：企业知识增强员工服务 Agent

## 1. 数据边界

本项目有五类数据，每类数据的职责不同：

| 数据类型 | 载体 | 作用 |
| --- | --- | --- |
| 组织与身份数据 | `employees.json` | 确定员工、主管、部门负责人和权限范围 |
| 个人业务状态 | `leave_balances.json` | 提供当前年假余额 |
| 业务过程记录 | `leave_requests.json` | 记录申请及审批进展 |
| 确定性业务规则 | `approval_rules.json` | 决定校验和审批逻辑 |
| 制度知识 | RAG 文档 | 解释制度原文并提供引用依据 |

核心原则：

- 余额和审批状态必须来自结构化业务数据。
- 审批规则由后端执行，不能由模型自行决定。
- RAG 负责解释“为什么这样规定”，不负责计算余额或修改申请。

## 2. 员工数据

文件：`employees.json`

| 字段 | 类型 | 说明 | 规则 |
| --- | --- | --- | --- |
| `employee_id` | string | 员工唯一编号 | 全局唯一，不可为空 |
| `name` | string | 员工姓名 | 不可为空 |
| `department` | string | 所属部门 | 必须与主管部门一致 |
| `position` | string | 职位 | 用于展示和业务解释 |
| `work_years` | integer | 累计工作年限 | 不能为负数 |
| `manager_id` | string/null | 直属主管编号 | 普通员工必填，主管可为空 |
| `department_head_id` | string | 部门负责人编号 | 必须指向现有主管 |
| `role` | string | 系统角色 | `employee`、`manager` 或 `admin` |

角色含义：

- `employee`：只能查询和操作自己的业务数据。
- `manager`：可以查看和审批自己下属的申请。
- `manager` 或 `admin` 发起自己的请假时，由总经理审批。
- 总经理保留审批权限，但不能审批自己的申请。

## 3. 年假余额

文件：`leave_balances.json`

| 字段 | 类型 | 说明 | 规则 |
| --- | --- | --- | --- |
| `employee_id` | string | 员工编号 | 必须存在 |
| `year` | integer | 余额年度 | 当前为 2026 |
| `leave_type` | string | 假期类型 | 当前只开放年假 |
| `total_days` | number | 年度总天数 | 不能为负 |
| `used_days` | number | 历史累计已用天数 | 0 <= 已用 <= 总额 |
| `remaining_days` | number | 剩余天数 | 必须等于总额减已用 |

口径约定：

- `used_days` 是截至当前日期的历史累计值。
- `leave_requests.json` 只提供近期与待处理申请，不负责还原全部历史。
- 待审批申请不立即扣减余额。
- 主管批准后才更新 `used_days`。
- 用户确认写操作时，后端必须再次检查余额，避免重复提交或并发超用。

## 4. 请假申请

文件：`leave_requests.json`

| 字段 | 类型 | 说明 | 规则 |
| --- | --- | --- | --- |
| `request_id` | string | 申请唯一编号 | 全局唯一 |
| `employee_id` | string | 申请人 | 必须存在 |
| `leave_type` | string | 假期类型 | 当前为年假 |
| `start_date` | date | 开始日期 | 格式 `YYYY-MM-DD` |
| `end_date` | date | 结束日期 | 不得早于开始日期 |
| `days` | number | 申请天数 | 0.5 的整数倍 |
| `reason` | string | 请假事由 | 不可为空 |
| `status` | string | 申请状态 | 只能使用固定枚举 |
| `approver_id` | string | 审批人 | 必须是合法主管 |
| `submitted_at` | datetime | 提交时间 | ISO 8601 格式 |
| `approved_at` | datetime | 批准时间 | 已批准时必填 |
| `rejected_at` | datetime | 拒绝时间 | 已拒绝时必填 |
| `reject_reason` | string | 拒绝原因 | 已拒绝时必填 |
| `cancelled_at` | datetime | 取消时间 | 已取消时必填 |

业务申请状态：

- `待审批`
- `已批准`
- `已拒绝`
- `已取消`

注意：`待确认` 不属于正式请假单状态，而是 Agent 写操作动作的状态。

## 5. 待确认动作与请假单的区别

### 待确认动作

- 由 Agent 工具生成。
- 表示“即将执行，但尚未获得用户确认”。
- 必须有唯一动作 ID 和过期时间。
- 确认前不能创建请假单。

### 请假单

- 用户确认后才创建。
- 状态从 `待审批` 开始。
- 审批结果直接修改业务状态。
- 所有状态变化应保留操作人和时间。

## 6. 审批规则

文件：`approval_rules.json`

| 规则 | 当前口径 |
| --- | --- |
| 申请单位 | 0.5 天 |
| 提前申请 | 3 个工作日 |
| 工作日计算 | 排除休息日和法定节假日 |
| 3 天以内 | 直属主管审批 |
| 超过 3 天 | 部门负责人审批 |

边界解释：

- `3 天` 属于“3 天以内”，由直属主管审批。
- `3.5 天及以上` 属于“超过 3 天”，由部门负责人审批。
- 主管和管理员的请假统一由总经理审批。
- 当前版本不处理跨年度年假折算。
- 当前版本不处理法定节假日表，节假日判断留作后续扩展。

## 7. 数据真源与 Agent 权限

| 内容 | 真源 |
| --- | --- |
| 员工与主管关系 | `employees.json` 或对应数据库表 |
| 年假余额 | 余额表 |
| 请假状态 | 请假表 |
| 审批逻辑 | 后端规则服务 |
| 制度解释 | RAG 知识库 |
| 待确认动作 | 动作表或动作存储 |

Agent 的职责是选择工具并解释结果，不是替代上述真源。

## 8. 数据一致性约束

导入前必须满足：

1. 员工编号唯一。
2. 主管编号和部门负责人编号必须存在。
3. 普通员工与直属主管属于同一部门；总监级以上管理层可由总经理跨部门审批。
4. 每个员工每个年度只有一条年假余额。
5. `remaining_days = total_days - used_days`。
6. 申请编号唯一。
7. 申请人与审批人必须存在。
8. 状态必须属于允许枚举。
9. 申请天数必须是 0.5 的整数倍。
10. 3 天以内审批人为直属主管，超过 3 天审批人为部门负责人。
