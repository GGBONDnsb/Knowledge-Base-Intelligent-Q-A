# 面试演示场景

以下场景可作为同一套 Agent 的连续演示主线。建议按顺序执行，不要临时随机提问。

## 场景一：知识问答

员工问：年假可以休几天？

预期效果：
- Agent 调用知识库检索。
- 返回《年休假管理办法》中的天数表。
- 展示文档引用。

面试讲解点：说明 RAG 回答必须有依据，不依赖模型记忆。

## 场景二：查询个人年假余额

身份：E001 张三。

员工问：我今年还剩多少天年假？

预期效果：
- Agent 调用 `query_leave_balance`。
- 后端返回真实余额：剩余 3 天。
- 不经过 RAG，也不由模型编造。

面试讲解点：说明模型负责意图理解，业务数据由确定性服务提供。

## 场景三：规则与个人状态结合

员工问：我想请 4 天年假，应该找谁审批？

预期效果：
- Agent 检索制度，判断 4 天超过 3 天。
- 后端根据员工部门确定审批人是部门负责人李明。
- 回答中包含制度引用和审批人。

面试讲解点：RAG 不只回答制度，还能成为 Agent 决策依据。

## 场景四：余额不足时拒绝

身份：E003 王五。

员工问：帮我申请 2 天年假。

预期效果：
- 后端查余额：剩余 0 天。
- Agent 不创建申请。
- 回复说明余额不足，并建议改期或查询调休政策。
- 数据库没有新增请假单。

面试讲解点：写操作失败时，后端真实拦截，模型不能假装成功。

## 场景五：写操作人工确认

身份：E001 张三。

员工问：帮我申请 9 月 21 日至 22 日 2 天年假，事由是家中有事。

预期效果：
- Agent 查余额、查制度、校验日期。
- 生成待确认动作。
- 用户点击确认前，请假单不落库。

面试讲解点：说明人工确认、唯一动作 ID 和审计的重要性。

## 场景六：主管审批

身份：M001 李明。

主管问：我有哪些待审批的请假申请？

预期效果：
- 后端查询待审批列表。
- 显示张三的申请。
- 主管选择批准后，状态更新为已批准。

面试讲解点：说明同一 Agent 支持员工和主管两种角色，以及任务状态机设计。
