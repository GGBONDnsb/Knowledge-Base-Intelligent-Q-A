# 员工服务 Agent 验收清单

- 版本：v1.0
- 日期：2026-09-10
- 目的：验证数据、业务规则和 Agent 行为是否一致

## 一、数据校验

| 编号 | 检查项 | 通过标准 |
| --- | --- | --- |
| D01 | 员工编号 | 全部唯一，无空值 |
| D02 | 主管关系 | 普通员工与主管同部门；管理层由总经理审批 |
| D03 | 余额唯一性 | 同一员工、年度和假别只有一条记录 |
| D04 | 余额计算 | 剩余天数等于总额减已用 |
| D05 | 申请引用 | 申请人和审批人全部存在 |
| D06 | 状态枚举 | 只出现待审批、已批准、已拒绝、已取消 |
| D07 | 审批规则 | 3 天内由直属主管审批，超过 3 天由部门负责人审批 |
| D08 | 日期规则 | 结束日期不早于开始日期，天数为 0.5 的整数倍 |

## 二、业务场景验收

### A01 查询余额

输入：

- 当前身份：E001 张三
- 问题：我今年还剩多少天年假？

通过标准：

- 返回张三 2026 年剩余 3 天。
- 使用业务工具查询，不调用 RAG 猜答案。
- 数据库中的数据没有被修改。

### A02 余额不足

输入：

- 当前身份：E003 王五
- 问题：帮我申请 2 天年假。

通过标准：

- 后端识别王五剩余 0 天。
- 不生成正式请假单。
- 不返回“申请成功”。
- 建议用户改期或查询其他假别政策。

### A03 规则加个人状态

输入：

- 当前身份：E001 张三
- 问题：我想请 4 天年假，应该找谁审批？

通过标准：

- 检索《年休假管理办法》。
- 判断 4 天超过 3 天。
- 根据员工部门确定审批人为部门负责人。
- 回答同时包含制度和员工上下文。

### A04 生成待确认动作

输入：

- 当前身份：E001 张三
- 问题：帮我申请 9 月 21 日至 22 日的 2 天年假。

通过标准：

- 校验余额、日期和审批规则。
- 返回唯一待确认动作。
- 确认前请假单数量不增加。
- 待确认动作包含员工、日期、天数和事由。

### A05 确认后落库

操作：

- 确认 A04 生成的动作。

通过标准：

- 创建一条请假单。
- 初始状态为待审批。
- 返回申请编号。
- 重复点击确认不能创建第二条申请。

### A06 主管待办

输入：

- 当前身份：M001 李明
- 问题：我有哪些待审批的请假申请？

通过标准：

- 只返回李明权限范围内的下属申请。
- 能看到张三的申请。
- 看不到其他部门的申请。

### A07 主管审批

操作：

- 李明批准张三的申请。

通过标准：

- 申请状态变为已批准。
- 审批人和审批时间被记录。
- 如果采用批准后扣减口径，年假已用天数同步增加。

### A08 引用与业务结果共存

输入：

- 当前身份：E001 张三
- 问题：帮我请假，并告诉我制度为什么要求主管审批。

通过标准：

- 业务动作和 RAG 引用同时返回。
- 引用指向对应制度章节。
- 审批规则由后端执行，引用只负责解释。

## 三、回归验收

每次修改 Agent 后，至少重新执行：

- 原 RAG 知识问答测试。
- 24 个现有 pytest 用例。
- 25 条 Agent 任务评测。
- 本清单中的 A01-A08。

## 四、最终演示标准

- 演示过程中不需要手工修改数据库。
- 每一步都能说明是调用知识库还是调用业务工具。
- 写操作确认前没有落库。
- 余额不足时不会撒谎。
- 主管能看到真实待办并完成审批。
