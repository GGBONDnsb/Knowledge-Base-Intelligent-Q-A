# 研发代码管理规范

> 文档编号：YQ-INST-027
> 版本：v2.0
> 生效日期：2026-08-18
> 责任人：研发中心
> 权限级别：部门

## 1. 文档说明

本规范统一研发代码的分支管理、提交规范、代码评审和 CI/CD 要求，提升代码质量与可维护性。

## 2. 仓库管理

代码统一托管在公司内部 Git 服务，禁止将内部代码上传到公共平台。

仓库应包含 README、许可证（如适用）和必要的目录说明。

仓库访问按项目角色授权，离职时自动回收。

## 3. 分支策略

主干分支 main 保持可发布状态，功能分支从 main 创建并合并回 main。

发布分支用于版本维护，修复分支只包含紧急修复。

禁止直接向 main 提交，所有变更通过合并请求完成。

## 4. 提交规范

提交信息采用 Conventional Commits 格式，如 feat、fix、docs、refactor、test。

提交应保持逻辑独立，禁止把无关改动混入同一提交。

提交前检查密钥、内网地址和个人信息，禁止提交敏感内容。

## 5. 代码评审

合并请求至少一名拥有项目权限的评审人批准后方可合并。

评审关注正确性、安全性、性能、可读性和测试覆盖。

重大架构或安全相关变更应增加专项评审。

## 6. CI/CD

每次合并请求应自动执行构建、静态检查和测试。

生产环境构建使用可复现的流水线，产物带版本号和哈希。

测试覆盖率、安全扫描结果在合并前展示并作为质量门槛。

## 附则

1. 本制度由研发中心负责解释和修订，自发布之日起施行。
2. 本制度为模拟文档，仅用于知识库问答系统的学习演示，不代表任何真实企业的管理规定。
3. 如遇法律法规或公司经营情况变化，由相关责任部门提出修订，经审批后发布新版本。
